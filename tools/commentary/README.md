# 장별 요약 데이터 작업 안내서

## 비공개 업로드 자료 조회

두 성경 역본 132개 파일(각 66권·1,189장)은 저장소 밖 `/workspace/private-reference/bible/`에 보관한다. 원본은 수정하지 않고 절 번호의 누락·역본 차이를 보존한다. 모델 자체의 영구 학습이나 다른 환경으로의 자동 이전은 아니다.

```sh
python tools/commentary/private-scripture.py status
python tools/commentary/private-scripture.py passage gen 37 3 --commentary --commentary-chars 800
python tools/commentary/private-scripture.py search 에봇 --code exo --limit 4
```

필요한 절만 두 역본으로 대조한 뒤 업로드 호크마 정리를 해석 보조로 확인한다. 본문과 주석 해석이 다르면 본문을 우선하고 차이를 기록한다. 이미 정확한 설명은 유지한다. `--db` 또는 `PRIVATE_BIBLE_DB`로 다른 **저장소 외부** 경로를 지정할 수 있다. DB가 없으면 비공개 자료 연결부터 복원한다.

원문·DB·업로드 매니페스트는 Git이나 웹 배포에 넣지 않는다. 앱에는 새로 쓴 설명과 근거 구절만 반영한다. 도구는 오프라인 개발 조회 전용이며 앱 서버/API로 연결하지 않는다. 추가 가져오기는 비공개 매니페스트의 `result.path`를 읽는 `import` 명령으로 수행하며, 132개 파일·권별 장 수·중복 번호·DB 무결성을 검사한다.

오늘 분량 요약을 Gemini로 그때그때 만들지 않고, 1,189장 요약을 **미리 써 둔 파일**로 둔다.
앱은 하루 분량에 들어 있는 장들의 요약을 합쳐서 보여 준다(`js/features/summary-data.js`).
그날 분량의 장이 하나라도 파일에 없으면 예전처럼 서버(Gemini) 요약을 쓴다.

## 파일

- `data/summary/<책 코드>.json` — 권마다 하나 (책 코드는 `js/core/bible.js`의 `BOOKS`, 예: `rut`, `1sa`, `psa`)
- `tools/commentary/names.json` — 같은 사람·같은 곳을 하나의 이름으로 쓰기 위한 대표 이름 목록
- 주석 OCR 텍스트는 **저장소 밖**(`%LOCALAPPDATA%\daily-bible-reading\ocr`)에만 둔다. 저작권 자료라 절대 커밋하지 않는다.

## 서식

```json
{
  "book": "rut",
  "songs": [
    { "title": "곡 제목", "artist": "부른 사람", "why": "이 책과 어울리는 이유 40자 이내" }
  ],
  "chapters": {
    "1": {
      "type": "story",
      "line": "한 줄 요약",
      "story": "이야기",
      "events": [ { "title": "사건 이름", "verses": "1-5", "text": "무슨 일이 있었는지" } ],
      "people": [ { "name": "나오미", "role": "이번 장에서 한 일", "weight": 3 } ],
      "renames": [ { "from": "아브람", "to": "아브라함", "verses": "5", "why": "언약을 세우시며" } ],
      "rels": [ { "from": "룻", "to": "나오미", "label": "며느리", "kind": "family", "directed": true, "weight": 3,
                  "verses": "16", "note": "룻이 어머니가 가시는 곳에 나도 가겠다며 나오미를 떠나지 않았어요." } ],
      "places": [ { "name": "모압", "where": "어디에 있는 곳인지", "what": "여기서 일어난 일", "weight": 3 } ]
    }
  }
}
```

| 칸 | 규칙 |
|---|---|
| `type` | `story`(이야기) `law`(율법·제도) `list`(족보·명단·측량) `poem`(시·노래) `wisdom`(지혜) `prophecy`(예언) `letter`(편지·설교) `vision`(환상·묵시) |
| `line` | 120자 이내 한두 문장. 하루에 3장 이상 읽는 날 "한눈에 보기"에 쓰임 |
| `story` | 500자 이내, 3~7문장. 하루에 1~2장 읽는 날 그대로 보임. 흐름(무슨 일) → 의미(하나님은 어떤 분, 사람들은 어떻게 반응) 순서 |
| `events` | 2~5개, **장 안의 순서대로**. `title` 18자 이내, `verses`는 절 범위(`"1-5"`, `"16"`), `text` 70자 이내. 이야기가 없는 장은 "무엇을 말하는가"의 단락으로 쓴다(예: `title` "속죄제 규정") |
| `people` | 이 장에 이름이 나오고 **말하거나 행동하는 인물은 모두**(무리 포함, 많으면 12명까지). 비중 순서. `role` 24자 이내. `weight` 3=중심, 2=주요, 1=잠깐 |
| `renames` | (있을 때만) 이 장 안에서 이름이 바뀐 사람. `to`는 people에 있어야 함. `why` 12자 이내로 바뀐 계기("언약을 세우시며", "얍복 강 씨름 뒤"). 하루 분량에 이 장이 들어 있으면 관계도에 "옛 이름 → 새 이름" 화살표가 그려짐 |
| `rels` | `from`·`to`는 같은 장 `people`의 `name`과 글자까지 같아야 함. `label` 10자 이내, "from은 to의 label"로 읽히게(예: 룻 → 나오미 "며느리"). `kind`: `family`(가족·친척) `ally`(돕기·스승과 제자·동역) `conflict`(대립·반역) `other`. 서로 같은 관계(형제, 동역자, 원수)면 `directed: false` |
| `rels`의 `verses`·`note` | 관계도 상세 창(꾹 누르기)에서 그 관계를 누르면 나오는 **구절 풀이**. `verses`는 그 관계가 드러난 절(`"16"`, `"1-3"`, `"1, 16"`), `note`는 90자 이내. 새번역의 뜻을 따라 **쉬운 말로 풀어 쓰고 문장을 그대로 옮기지 않는다**. 누가 누구에게 무엇을 했는지(왜) 한두 문장. `renames`에도 `note`를 쓸 수 있음 |
| `places` | `where` 30자 이내(위치·어떤 곳), `what` 50자 이내(이 장에서 여기서 일어난 일). 2~4곳 |

하루 분량으로 합칠 때(장 수와 상관없이):
- 인물 목록은 그날 모든 장의 인물을 처음 나온 순서로 다 보여 줌(여러 장이면 나온 장 표시). 관계도에는 `weight` 합이 큰 9명까지
- 이름이 바뀐 사람은 목록에 "옛 이름 → 새 이름" 한 줄로
- 관계는 관계도 인물 사이의 것만, `weight` 순서로 11개 + 이름 바뀜 화살표
- 지역은 이름이 같으면 하나로, 6곳
- 사건은 하루 1~2장이면 장마다 4개, 3~4장이면 3개, 5장 이상이면 2개 (그래서 **중요한 사건을 앞에** 쓴다)
- 찬양은 그 분량에서 장이 가장 많은 권의 곡

## 쓰는 규칙

1. **관점**: 대한예수교장로회(합동), 칼뱅주의 개혁신학. 본문에 없는 신학 주장을 덧붙이지 않는다.
2. **말투**: 중학생에게 이야기하듯 쉬운 해요체. 어려운 한자어는 풀어 쓴다(언약 → 하나님과 맺은 약속).
3. **사실만**: 본문에 나오는 인물·관계·지명만. 확실하지 않으면 뺀다. 학자 이름·인용문을 지어내지 않는다.
4. **이름은 그 장 본문(개역개정)이 부르는 대로**: 창 12~16장은 아브람·사래, 17장부터 아브라함·사라 / 행 9장은 사울, 13장 이후 바울. 이름이 바뀌는 장에는 `renames`를 적는다(목록은 `names.json`). 하나님·예수·성령은 표기를 `names.json`대로 통일.
5. **주석 문장을 옮기지 않는다.** 주석은 사실 확인용으로만 읽고, 글은 새로 쓴다.
6. **관계도에 힘을 싣는다**: 이야기 장은 관계를 3~6개. 가족 관계만 나열하지 말고 그 장에서 **움직인 관계**(도움, 대립, 배신, 화해, 명령과 순종)를 넣는다.
7. **사건**: 제목만 봐도 흐름이 보이게. `text`에는 누가, 무엇을, 왜/결과를 한 문장에.
8. **지역**: `where`는 지도 없이도 감이 오게("사해 동쪽 고원 지대", "예루살렘 남쪽 약 9km"). `what`은 그 장에서 그곳의 의미.

## 작업 순서

```bash
# 1) 주석 OCR (처음 한 번, 30~60분. 이미 된 권은 건너뜀)
node tools/commentary/ocr.mjs

# 2) 쓸 장의 주석 본문 보기 (해당 장 쪽만 뽑아 줌)
node tools/commentary/chapter.mjs rut 1

# 2-0) 성경 본문을 글자로 뽑기 (캡처 이미지보다 토큰이 적게 듦. 갓피아 본문, 저장소에 커밋 금지)
node tools/commentary/bibletext.mjs 2sa 15-17 han,easy   # --plain(본문만) --save(.bible-cache에 저장)

# 2-1) 관계마다 구절 풀이 붙이기: 관계 목록 보기 → 묶음 파일 작성 → 붙이기
node tools/commentary/rels.cjs gen 1 25
node tools/commentary/addnote.cjs 묶음.json   # { "gen 22": [[from, to, 절, 풀이, (label)]] }

# 3) data/summary/<책>.json 작성 후 검사 (서식·글자 수·이름 대조)
node tools/commentary/check.mjs rut
node tools/commentary/check.mjs          # 전체
```

`check.mjs`의 "주석에 없음"은 인물·지명이 그 장 주석(개역개정 본문 포함) 쪽에서 글자로 찾아지지 않았다는 뜻이다. OCR이 글자를 잘못 읽은 경우(룻→롯)도 있으니 경고를 보고 직접 판단한다.

## 빠르게 쓰는 도구

- `compact.cjs <묶음.json>`: 짧은 형식(`t,l,s,e,p,r,g,n`)으로 쓴 여러 장을 합치고 바로 검사. `r`은 `[from, to, "f>", label, 비중]`(f 가족·a 동역·c 대립·o 기타, `>` 방향 있음·`-` 서로), `n`은 `[옛 이름, 새 이름, 절, 계기]`
- `fix.cjs <책> <장> "<JS 코드>"`: 한 장을 코드로 고침
- `addp.cjs <묶음.json>`: 이미 쓴 장에 빠진 인물을 덧붙임
- `trim.cjs <책> [500]`: 글자 수를 넘긴 story에서 인용 없는 문장부터 덜어 냄(뺀 문장을 출력하니 핵심이 빠졌으면 다시 넣기)
- `commit.sh "<메시지>"`: 전체 검사 오류가 0일 때만 커밋·푸시
