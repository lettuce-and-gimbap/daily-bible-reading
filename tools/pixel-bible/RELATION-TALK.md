# 관계도 조우 대화 작성 규칙

픽셀 월드에서 관계선으로 이어진 두 인물이 옆 칸에서 만나거나 TV 부스에 함께 서면 대화를 나눈다.
관계가 없는 두 사람만 "어… 안녕하세요."라는 어색한 인사를 한다. 관계가 있으면 반드시 그 관계와 그 장의 사건에 맞는 대화를 한다.

- 저장 위치는 `data/pixel-bible/relation-talk/<book>.json`이다.
- 키는 `"장|from|to"`이고, 값은 `[[from의 말, to의 답], [from의 말, to의 답]]`이다.
- 앱은 이 대화를 기존 `pair-dialogue.js`보다 먼저 쓴다.

## 도구

```bash
node tools/pixel-bible/relation-talk.mjs todo <book> [장 또는 장-장]   # 아직 대화가 없는 관계
node tools/pixel-bible/relation-talk.mjs todo <book> 3-5 --all        # 이미 쓴 것까지 모두
node tools/pixel-bible/relation-talk.mjs apply <patch.json>           # {"<book>":{"장|from|to":[[..,..],[..,..]]}}
node tools/pixel-bible/relation-talk.mjs check <book>...              # 형식·길이 검사(오류 0이어야 함)
```

`todo`가 줄마다 보여 주는 정보는 다음과 같다.

| 표시 | 내용 |
|---|---|
| `KEY` | 키, 인물(역할), 관계 이름/종류, 절 |
| `NOTE` | 관계 설명 |
| `VERSE` | 해당 절의 개역개정 본문(저장소 밖 자료). 출력만 하고 저장하지 않는다. |
| `HAS` | 이미 있는 고유 대사(pair-dialogue) |

하나님·여호와·성령·주님과의 관계선은 월드 인물이 아니므로 대상에서 빠진다.

## 작성 원칙

1. **근거를 먼저 확인한다.**
   - `VERSE`와 `NOTE`를 먼저 읽는다.
   - 사건 앞뒤 흐름이 불분명하면 아래 두 파일에서 해당 장을 찾아 읽는다. 장 머리는 `## N장`이다.
     - `C:/Users/sam04/OneDrive/Desktop/소명/교회/주석/원문_md/개역개정4판_<번호>_<book>_<권명>.md`
     - `C:/Users/sam04/OneDrive/Desktop/소명/교회/주석/호크마_md/호크마_<번호>_<권명>.md`
   - 본문 사실(누가, 무엇을, 언제)과 어긋나는 말은 쓰지 않는다.
   - 신학 관점은 장로교 합동 개혁주의 관점이다.
2. **관계에 맞는 말을 한다.**
   - 관계별로 이런 말을 한다.

     | 관계 | 할 말 |
     |---|---|
     | 부자·모녀 | 가족끼리 할 말 |
     | 왕과 신하, 지휘관과 부하, 명을 받은 제사장 | 명령과 충성의 말 |
     | 선지자와 왕 | 말씀 전달과 반응 |
     | 원수 | 맞서는 말 |
     | 스승과 제자 | 가르침과 배움 |
     | 사도와 교회 | 권면과 감사 |

   - 호칭과 말투를 관계에 맞춘다.
     - 왕에게는 "왕이시여, ~하옵소서/~하겠습니다", 왕은 "~하라/~하겠다"라고 한다.
     - 부모는 "아들아/딸아", 자녀는 "아버지/어머니"라고 부른다.
     - 부부는 "여보/당신"이라고 부른다.
   - 둘째 줄은 반드시 첫째 줄에 대한 **답**이다. 따로 노는 혼잣말 두 개를 쓰지 않는다.
   - 그 장의 **구체적 사건, 장소, 물건, 결정**이 드러나야 한다. 예: 율법책, 성전 수리, 골리앗의 칼.
   - 어느 장에나 붙일 수 있는 일반론은 쓰지 않는다. 예: "서로 맡은 책임을 나눕시다".
3. **형식을 지킨다.**
   - 한 줄은 12~80자이고, 말풍선에 들어갈 만큼 짧은 구어체로 쓴다. 보통 25~60자가 알맞다.
   - 관계 하나에 2쌍을 쓴다. 두 쌍은 다른 각도로 쓴다. 예: 사건의 시작과 결과, 감정과 결심.
   - "안녕하세요/반갑습니다" 같은 빈 인사는 쓰지 않는다.
   - 개역개정 문장을 길게 그대로 옮기지 않는다. 짧은 핵심 어구만 쓰고 나머지는 쉬운 말로 풀어 쓴다.
4. **기록이 적은 관계도 이렇게 쓴다.**
   - 족보 관계처럼 기록이 적으면 그 장이 말하는 사실을 쓴다. 예: 이름의 뜻, 땅 분배, 계보가 이어지는 의미.
   - 사건을 지어내지 않는다.
   - 시대가 떨어진 조상·후손이 만나도 본문이 말하는 연결을 짚는다. 예: 약속이 이어짐, 왕위의 계보.
5. **이미 있는 대사(HAS)는 이렇게 다룬다.**
   - 기본은 그대로 둔다. `todo` 기본 출력에도 나오지만 대상이 아니다.
   - 관계에 맞지 않거나 본문과 어긋나거나 어색할 때만 talk을 써서 덮는다.
6. **비유와 상징 인물(시편·계시록 등)은 이렇게 다룬다.**
   - 본문이 그리는 역할 그대로 말한다. 예: 원수와 시인, 어린양과 장로들.
   - 예수님의 말씀은 복음서에 기록된 취지를 벗어나지 않는다.


## 작업 순서

1. `todo`로 한 번에 10~20장씩 본다.
2. 패치 JSON을 scratchpad에 쓴다.
3. `apply`로 반영한다.
4. `check <book>`에서 오류 0을 확인하고, 다음 장으로 넘어간다.

git 커밋은 하지 않는다. 맡은 권 외의 파일은 건드리지 않는다.
